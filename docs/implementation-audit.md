## AI result interpretation

The saved [v2.0.0 evaluation report](../ai/docs/model_evaluation.md) records 305 train examples (80/148/77) and 42 test examples (24/0/18), with 100% accuracy on each reported set. EMPTY/OCCUPIED test precision and recall are 100%; INVALID has zero support, and the report displays zero precision/recall for it. No deployment-wide accuracy or F1 claim is inferred.

The current `ai/data/test/` contains 48 image files by extension (26 EMPTY / 3 INVALID / 19 OCCUPIED), so the old report does not describe the current test inventory. This is a file count, not a new evaluation; no new confusion matrix was generated. The following also limit reproduction/interpretation:

- Training images and the `.pth` training checkpoint are absent; the serving model and test photos require LFS materialization. Grad-CAM reconstructs the `.pth` model, not the TorchScript artifact alone.
- Metadata's `accuracy` is the best validation argmax accuracy recorded by training, not the saved report's test metric. `/model/info` only republishes it.
- Evaluation converts UNKNOWN to the highest-probability trained class. The application instead rejects UNKNOWN as `AI_SERVER_ERROR`; reported classification accuracy does not measure abstention or automatic/manual return acceptance rates.
- The training script randomly splits a directory of augmented images and uses one augment-enabled dataset for both subsets. It does not group variants by original image or turn off random transforms for validation. Split independence and deterministic validation are not demonstrated.
- The historical CLAHE report records an unchanged 85.7% result and a hypothesis about low-contrast sample scarcity. It is not a reproduced causal experiment or proof of an improvement in the current artifact.
- The repository provides no comparative architecture benchmark, calibrated-confidence analysis, or substantiated sustained inference-throughput result.
